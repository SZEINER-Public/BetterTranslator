# Blocked at L4

Items that could not be consumed at L1, L2 or L3. Each proposal is the smallest change to the original that would unblock it, written for a later run. Nothing outside `mac/` was changed in this run.

| Item | Why L1 fails | Why L2 fails | Why L3 fails | Proposal |

| `src/BetterTranslator.Runtime/Inference/BetterRuntime.cs` native library resolution | the assembly loads at L1 but the `Native` static ctor claims the assembly's only `DllImportResolver` slot (`BetterRuntime.cs:80-84`); a second `SetDllImportResolver` for the same assembly throws | a mirror compiles the same source, so the mirror's `Native` cctor claims the slot identically | `AssemblyLoadContext.Default.ResolvingUnmanagedDll` fires only after the primary resolver returns `IntPtr.Zero`, and `ResolveFlavor` throws `DllNotFoundException` instead (`BetterRuntime.cs:165`); a shim cannot reach past a throwing resolver | in `ResolveFlavor`, return `IntPtr.Zero` rather than throwing when no flavour loads, and let the caller surface `Finding`; or guard the `SetDllImportResolver` registration with `OperatingSystem.IsWindows()`. Either lets a host-registered `ResolvingUnmanagedDll` handler supply `libBetterRuntimeCPU.dylib`. The wrapper's `MacNativeRuntime` already subscribes that event and is inert until this lands |
| `src/BetterTranslator.Runtime/Inference/RuntimeSupport.cs` physical load path | `LoadScoped` calls `LoadLibraryExW` and `AddDllDirectory` from `kernel32.dll` (`:141-145,153-174`), which throw `DllNotFoundException` on macOS | the mirror compiles the same two `DllImport` declarations | a shim cannot substitute a method body inside a linked file, and supplying a native `kernel32` stub means building a native artifact, which is out of scope for this run | guard `LoadScoped` with `OperatingSystem.IsWindows()` and fall back to `NativeLibrary.TryLoad(path)`; make `VisualCppModules` empty off Windows so `MissingBeside` stops reporting `Incomplete` before any load is attempted (`:30-31,101-104`) |
